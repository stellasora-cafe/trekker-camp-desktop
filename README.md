# 旅人营地桌面客户端

[下载桌面客户端](https://github.com/stellasora-cafe/trekker-camp-desktop/releases) · [0.1.2 及更早版本](https://github.com/stellasora-cafe/trekker-camp/releases)

正式客户端使用 Go 1.27.3 和 [MyGo v0.10.0](https://github.com/egoist/mygo/releases/tag/v0.10.0) 托管完整前端，Windows 使用系统 WebView2。页面、控件、MFM、动画和路由直接复用本站前端；登录或注册时从服务器按需加载页面，完整前端包在页面显示后后台下载到安装目录，后续使用缓存并检查更新。安装器和 EXE 不携带前端 ZIP。Go 外壳负责窗口、桌面设备协议、持久会话和资源缓存。发布版默认连接 `https://camp.stellasora.cafe`；开发版与 `go run .` 默认连接 `http://localhost:3000`。

正式入口是本目录的 `main.go`，应用逻辑位于 `internal/webclient/`。启动时在本地读取当前站点的加密登录会话：已登录直接进入营地并复用已有前端与浏览器缓存，更新在页面显示后后台检查；未登录显示原生欢迎页，使用正常账号登录；运行和发布均不依赖验收账号、fixture 或 `artifacts/local-ui-accounts.json`。

每次从欢迎页完成登录后，主窗口从服务器加载前端。后台下载同一版本供下次启动和离线使用，不会出现“刷新并更新”；只有运行中的页面与服务器版本不同时才会提示。

MyGo 源码固定在 `third_party/mygo`，保留独立的 MIT 许可证，通过 `go.mod` 的本地替换供运行时与构建工具共同使用。修改与回归记录见 [CAMP_PATCHES.md](third_party/mygo/CAMP_PATCHES.md)。

## 开发与构建

在仓库根目录安装测试和发布脚本所需的依赖，再使用 Go 开发或构建：

```sh
pnpm install --frozen-lockfile
go tool mygo dev
go tool mygo build -platform windows/amd64 -skip-installer
go run . --url http://localhost:3000 --data-dir ./artifacts/local-client/webview
```

开发与在线功能验收先按 [本地开发指南](https://github.com/stellasora-cafe/trekker-camp/blob/master/SETUP.zh-CN.md) 启动本站开发服务器。`--url` 指定站点，`--data-dir` 指定独立用户数据目录；持久浏览器会话按站点 origin 与数据目录隔离。日常开发与验收使用本地账号和本地数据。原生欢迎页可直接启动；进入登录或注册时才检查服务器的前端兼容清单，网页按需联网加载所需资源，已有可用缓存时复用缓存。

本地服务器首次提供桌面前端，或修改网页源码后，在服务端仓库执行 `pnpm desktop:frontend`。该命令构建生产前端、动态模块、worker、两种中文翻译及公开静态资源，只发布到服务器的 `built/_desktop_frontend_/`。`go tool mygo build` 仅构建宿主和安装器，不执行前端构建。发布的 EXE 不需要 Node.js、pnpm 或本机网页服务器。

Windows 产物位于 `build/windows-amd64/`。省略 `-skip-installer` 会通过 MyGo 打包安装程序。构建不需要 cgo，EXE 不内嵌独立 Chromium。应用图标使用仓库中的公开品牌素材；正式安装器内置 MiSans 和关于页图像，其余独立授权素材保持运行时加载。

## 窗口与本地资源

未登录时显示 420×460 的不透明原生欢迎卡，保留最小化与关闭，最大化灰置。欢迎卡启动时不主动检查连接，登录和注册按钮保持可用。点击后进行轻量 manifest 兼容检查，检查期间按钮禁用并显示转圈；失败在原生卡内显示红色提示，恢复按钮供重试。检查通过后，注册和登录各打开独立的小型网页窗口，通过 `/desktop-auth` 路由直接联网加载并复用浏览器缓存；页面显示后后台下载、暂存其余前端资源。更多菜单打开只显示内容区的工具窗口。登录后的主窗口可调整大小，MyGo 保存其位置与尺寸。Windows 窗口使用沉浸式自绘控制区：页面延伸到顶部，页面顶栏与窗口控件采用 50 DIP 的共同高度，右上角三个按钮统一为 42×50 DIP、10px 细线图形，不显示额外名称或标识。页面顶栏空白可拖动和双击最大化，页面按钮保持原有交互；保留系统圆角、阴影、边缘缩放及拖动贴靠。页面操作和小工具避让窗口按钮；桌面 Deck 将现有工具栏融入顶行，列保留原布局与拖列交互。原生欢迎卡与权限窗口沿用相同的控件高度和拖动范围。窗口状态从宿主同步，断网维护页仍可操作窗口。工具窗口等待前端和窗口控件就绪后显示。站内页面继续在应用中打开，外链交给系统浏览器。桌面外壳隐藏登录后和游客侧栏的滚动条，保留滚轮与键盘滚动；导航吸顶区使用主题背景遮挡滚过的文字，避免渐变模糊层覆盖菜单。普通网页不受这些桌面样式影响。

Windows 的 `internal/webfrontend/` 可在原站点 origin 下直接响应缓存的 HTML、JS、CSS、worker 与公开资源，保留原站点账号存储。登录与注册窗口直接从服务器加载 `/desktop-auth`，按浏览器缓存取得当前页面需要的资源，无需等待完整前端 ZIP。完整前端包另在后台暂存，包含 Shiki 语言和主题。加载器及未带版本的文件要求重新校验，带哈希的模块可长期缓存，应用升级后使用新包。启动探测页由宿主本地响应，不访问服务器，不清空浏览器缓存、账号或偏好。当前同源资源拦截由 Windows WebView2 实现；其他平台继续使用站点加载路径。

欢迎页的更多选项使用原生自绘浮层；桌面输入框、选中文字、链接、图片和媒体的右键菜单沿用营地菜单组件及主题。帖子已有的业务菜单继续保留。粘贴由用户点击后通过同源窗口的限定宿主接口读取文本，网页保留编辑选区与撤销记录；维护页的菜单位于维护层内。网页和 PWA 的窗口与右键菜单行为保持原有设置。

`internal/webassets/` 预缓存 MiSans Regular、Medium、Semibold、Bold 四个 WOFF2、Tabler 图标 CSS 与字体、少量公开品牌图和维护提示插图。桌面使用独立字重映射：400 正文使用 Regular，500／600／700 分别使用 Medium／Semibold／Bold，保持网页字号、行高和加粗语义；普通网页的字重映射不变。启动时直接读取当前站点的已有资源，不等待联网；后台再使用 ETag／Last-Modified 校验。字体优先读取安装目录 `resources/camp/fonts/misans-v1/`；无随附字体的源码构建使用缓存或系统字体。维护插图联网下载到 resource-cache/；前端 ZIP 和公开源码资源目录不包含私有字体或维护插图。

已访问的时间线、帖子详情、用户和部分只读列表按站点、账号及请求参数保存到 IndexedDB，最多 160 条记录、16 MiB；时间线中的帖子同时保存详情。已查看的同源公开图片由 `internal/webmedia/` 保存，磁盘上限 256 MiB。账号会话与主题、布局等客户端偏好继续在本地保存。本地断网或普通连接失败时保留当前页面、已加载内容和客户端设置，显示连接提示与手动刷新按钮。只有应用入口、API 或更新地址重定向到 `/__camp-maintenance/v1.html` 时显示维护页；原生宿主每 15 秒直接检查应用入口，绕过本地 HTML 拦截。维护页保留重连按钮和待开放的“离线使用星塔工具箱”入口。服务恢复后关闭维护页并恢复原页面。

内容缓存限已读取且列入缓存范围的只读 API 数据与公开图片；视频不主动保存，实时聊天、上传及其他在线功能需要网络。

Windows 运行期间托盘图标常驻。登录后首次关闭主窗口时，可选择收进托盘或退出应用。选择保存在本机，可在「设置 → 偏好设置 → 常规设置 → 关闭按钮行为」中更改。未登录时关闭欢迎页会直接退出。收进托盘会隐藏窗口并保留 WebView，点击托盘图标或再次从桌面启动会回到原来的页面。托盘期间沿用网页的实时连接，通知和心链消息通过 Windows 系统通知呈现。网页静音，系统通知提示音遵循系统和营地的静音设置。右键托盘图标可以退出应用。

MiSans 位于素材库的 `public/fonts/misans-v1/`，正式桌面包随附五个字体文件及原许可，关于页保留字体署名及官方许可链接；缓存与公开资源分目录保存，不嵌入网页代码包。开发素材链接与授权约定见 [ASSETS.md](https://github.com/stellasora-cafe/trekker-camp/blob/master/ASSETS.md)。四个 WOFF2 约 18.99 MiB；已下载前端、运行时资源缓存与浏览器用户数据应分别统计，实际磁盘占用随站点与使用情况变化。

权限确认使用独立的 MyGo 原生窗口，显示站点、用途和选择按钮，等待决定时网页继续运行。该窗口由 `internal/webclient/` 的轻量界面实现，仅额外按需加载并缓存一个 MiSans Regular TTF。下载通过原生保存对话框选择位置。

## 前端在线更新

服务器构建同时发布独立的 `/_desktop/frontend/manifest.json` 与按内容哈希命名的完整 ZIP。进入网页后的启动流程、恢复连接及运行期间定期检查这个入口，网页继续使用原来的前端入口；业务请求保持 `/api/client/` 与 `/client-streaming`。普通前端修改随服务器发布即可更新桌面，无需重新分发安装包。

下载完成后校验大小、SHA-256、宿主协议版本与包内必需资源，再保存到按服务器隔离的本地缓存。进入网页后、重连和每 5 分钟检查一次更新。下载只保存待用版本，运行中的界面保持原版本；下次启动应用新版本，也可点击“刷新并更新”立即应用。空白发帖框不阻止刷新；存在编辑内容、表单或对话框时先确认是否继续。每个窗口固定使用同一版本资源，账号、偏好和草稿保留。新版本须完成页面启动确认，超时或启动中断会回退到上一可用版本。首次登录或注册的兼容检查失败时，在原生欢迎页显示可重试的错误；后台完整包下载失败保留已打开的网页，不阻塞登录。已登录时断网重启仍保留加密登录会话并加载缓存界面；连接恢复后自动刷新账号和实时连接，无需重新登录。本地断网保留当前页面并显示手动刷新入口。首次启动会在后台探测服务端维护，不阻塞原生欢迎页；即使没有前端缓存也能显示独立维护弹窗。登录、注册及兼容清单的维护重定向会打开同一弹窗，隐藏刷新和离线工具按钮；维护涉及的入口全部恢复后关闭弹窗，继续原登录或注册页面。

`pnpm build` 和 `pnpm desktop:frontend` 均在服务端仓库生成 `built/_desktop_frontend_/`。原生窗口、系统集成和宿主协议升级仍需更新桌面安装包；当前宿主仅接受 `hostApi: 2` 的前端包（包含系统凭证保护桥接）。独立授权素材位于安装目录的独立资源缓存，不进入前端更新 ZIP；程序更新归档携带宿主、内置关于页、白名单字体与关于页图像及法律声明。

桌面登录窗口及登录后的营地 Logo 菜单提供“检查更新”，同时检查前端和完整应用版本。普通网页与 PWA 不显示桌面更新入口。包体更新重启前保存可恢复的本地发帖草稿；上传、提交或未接入保存机制的编辑器会阻止重启。

## 登录与数据

登录和注册在独立网页窗口中沿用本站完整验证流程，登录成功后关闭验证窗口并进入主界面，签发独立的桌面设备会话。账号、网页草稿与偏好保存在当前站点对应的持久浏览器会话中，关闭窗口后保留；退出或切换账号沿用网页操作。设置中的“登录设备”管理网页与桌面设备，第三方应用授权单独管理。

登录窗口提供“从浏览器登录”：系统浏览器打开本站授权页，可复用浏览器登录状态，或完成密码、验证码、Passkey 验证后授权。桌面窗口等待授权并领取独立设备会话，支持重新打开浏览器、取消及过期后重试。领取密钥仅在当前窗口内存中保存，不出现在浏览器地址或本地存储中。直接登录时，已启用双重认证的账号可在 Passkey 与验证码之间切换；取消或重试 Passkey 会重新申请验证请求。

`internal/campweb/` 将桌面中的同源业务请求接入 `/api/client/<endpoint>`，使用 `X-Camp-Client: desktop-v1` 和 `Authorization: Bearer <会话>`；实时连接使用 `/client-streaming`。上传保留 XHR 的进度与取消，网页负责消息订阅和重连。显式匿名请求、账号切换及插件令牌保留各自身份。服务器复用本站业务服务与权限检查，协议约定见 [账号与 API](https://github.com/stellasora-cafe/trekker-camp/blob/master/AUTH.zh-CN.md#客户端会话与第三方-api)。

## 安装目录与凭据保护

Windows 安装器默认安装到 `%LOCALAPPDATA%/Programs/TrekkerCamp/`，支持开始菜单入口、桌面快捷方式及系统卸载。交互卸载可同时清除默认本机数据、WebView2 缓存和正式站点的本机加密密钥。静默卸载保留用户数据。安装目录可写，无需管理员权限：

```text
安装目录/
├── TrekkerCamp.exe
├── resources/                 随完整程序包替换的素材与许可证
├── resource-cache/<origin>/   下载的字体、插图等；不受包体替换影响
└── frontend-cache/<宿主版本>/<origin>/  前端热更新、待用版本和回滚状态
```

浏览器会话、设置、草稿及私有媒体继续保存在用户数据目录。`--data-dir` 仅改变这部分状态；开发模式的应用资源放在该目录下的 `application/`，避免写入 Go 临时编译目录。首次升级保留原目录，复制已有字体与插图到安装目录；旧协议的前端缓存保留原地，新宿主按需加载匹配的前端，并在页面显示后后台准备完整缓存。不同宿主版本隔离热更新，防止旧前端覆盖新版宿主基线。

Windows 凭据管理器保存按站点和用户数据目录隔离的随机密钥，使用 AES-256-GCM 保护浏览器中持久化的当前账号及 Pizzax 状态（含多账号和插件令牌）。网页读取旧格式时先保存密文，再继续使用；密钥或加密操作失败时停止持久化，不写明文后备。密钥不放入安装目录、安装器或热更新包。Web 与 PWA 保持各自原有存储流程。

程序更新检查在启动后及重连时执行，运行期间每 6 小时检查。发现新版本后通过原生窗口确认下载，验证签名后替换程序和随附资源；再次确认重启后生效。存在编辑内容、附件、投票、上传或其他工具窗口时暂停更新和重启。前端热更新仍每 5 分钟检查，下载后下次启动应用，或通过“刷新并更新”切换。

Windows 缺少或损坏 WebView2 Runtime 时，客户端先显示原生引导窗口，提供微软官方 WebView2 下载页和安装后重新启动按钮。安装器在安装完成时检测；交互安装可确认打开官网，静默安装不打开浏览器。运行时检测复用 MyGo 实际加载器，支持按用户、按机器和固定版本目录。
